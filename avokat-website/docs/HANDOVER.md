## 1. What was built

An **Albanian-language** website for an individual lawyer, built with Astro 7 (TypeScript),
served by a small Node.js server.

**Brand.** The supplied seal logo is used unmodified (1:1 proportions; the white background was made
transparent – master in `brand/logo-seal.png`, original in `brand/logo-original.jpg`). The palette is derived
from the logo: navy `#0c1d38` (logo navy `#011531`, lifted slightly for large areas) and gold
(`#d6a94f` on dark backgrounds, darkened to `#8a611c` on light backgrounds for readable contrast), on warm
ivory. Typography: Cormorant Garamond (headings) + Inter (text), both self-hosted – no Google Fonts requests.

**Confirmed information used** (from the business card and logo): name *Gentjan Gega*, title *Avokat*, practice
name *Studio Ligjore Gega*, phone *+355 68 201 0636*, email *gentjangega.lawoffice@gmail.com*, domain
*gegaattorney.al*. Nothing else about the lawyer was invented.

### Forms

* **Contact form** – name, email, optional phone, service, message, privacy acknowledgment.
* **Appointment request** – service, name, email and/or phone, preferred date, preferred time (from the
  configured schedule), meeting mode (office / video / phone), optional short note, privacy acknowledgment.
* It is an **appointment request system**, not a live calendar: the success message and the email to the lawyer
  both state that the time is *not confirmed* until the lawyer contacts the visitor.
* Weekends, past dates, today, dates beyond 60 days, configured closed days and times outside the schedule are
  rejected in the browser **and** on the server.
* Protection: honeypot field, signed time-token (rejects submissions faster than 3 s or older than 2 h),
  per-IP rate limit (5 per 10 min per form), idempotency key (double clicks / retries never send twice), JSON-only
  endpoints, 16 KB body limit, input normalisation (control characters / header injection stripped).
* Success is shown **only** after the email transport reports success. If email is not configured or fails,
  the visitor sees an error asking them to call or email directly.
* Submissions are **not stored** on the server (no database). They exist only in the lawyer's mailbox.
* Notices: no confidential details/documents; a submission does not create an attorney–client relationship.

### Security and privacy

* Content-Security-Policy (hash-based, generated by Astro per page) + `frame-ancestors 'none'`, HSTS,
  `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` (see `server.mjs`).
* No cookies, no analytics, no third-party scripts, fonts or embeds → **no cookie banner is required** in the
  current configuration. If analytics, a map embed, reCAPTCHA or similar is added later, a consent mechanism and
  a cookie-policy update are needed first.
* **Indexing is off by default** (`noindex` + `robots.txt: Disallow: /`) so a preview with placeholders is never
  indexed. Set `ALLOW_INDEXING=true` at build time only after the content is approved.

## 2. Recommended hosting

I could not inspect the current DNS/hosting of `gegaattorney.al` (this environment's network policy blocks
outbound DNS/HTTP to that host), so the recommendation assumes nothing is configured yet. If something is
already hosted there (e.g. an existing email setup or site), share the registrar/DNS details first – especially
**MX records must be preserved** if email is used on the domain.

**Recommendation: Render – one "Web Service" (Starter), region Frankfurt (EU).**

* Why: runs the Node server as-is (forms need a server), automatic HTTPS (Let's Encrypt), deploys from Git,
  no server maintenance, EU data centre (shortest path to Albania; simpler privacy story than US-only regions).
* Cost: Starter web service is listed at **$7/month** (512 MB RAM) on
  [render.com/pricing](https://render.com/pricing), with 100 GB bandwidth included on individual plans –
  far beyond what this site needs. *Do not use the free tier for production:* it sleeps when idle, so the first
  visitor waits ~30–60 s. Verify the price at sign-up; I have not signed up for anything.
* Alternatives: any Docker host (a `Dockerfile` is included) – e.g. a small EU VPS (cheaper, but you maintain the
  OS, updates and TLS yourself), or an Albanian host offering "Node.js app" (cPanel/CloudLinux) hosting: upload
  the build and run `node server.mjs` with the environment variables below.

### Deploy on Render (step by step – requires your account and approval)

1. Push this folder to a **separate GitHub repository** (recommended – see §8), e.g. `gegaattorney-website`.
2. Render → *New* → *Web Service* → connect the repository → Region **Frankfurt**.
3. Settings:
   * Root directory: the folder containing `package.json` (repository root if it's a separate repo; `avokat-website` if left in this repo)
   * Runtime: **Node**
   * Build command: `npm ci && npm run build`
   * Start command: `npm start`
   * Instance type: **Starter**
4. Environment variables (see §4). Set `SITE_URL=https://gegaattorney.al`, and keep `ALLOW_INDEXING=false`
   until the content is approved.
5. Deploy, then open the `*.onrender.com` URL and run through the checklist in §7.
6. Custom domain: Render → service → *Settings* → *Custom Domains* → add `gegaattorney.al` and
   `www.gegaattorney.al`. Render shows the exact DNS records to create (next section).

### DNS records (at the domain's registrar / DNS provider)

Use the values Render displays for your service; typically:

| Host | Type | Value |
| --- | --- | --- |
| `@` (gegaattorney.al) | `A` | the IP address Render displays for apex domains (Render's docs have listed `216.24.57.1` – always use the dashboard value) |
| `www` | `CNAME` | `<your-service>.onrender.com` |

* Remove any other `A`/`AAAA` records on `@` and `www` that point to an old host.
* **Do not touch `MX` / `TXT` (SPF, DKIM) records** used for email.
* HTTPS certificates are issued automatically once DNS propagates (minutes to a few hours). The canonical URL
  is `https://gegaattorney.al/` – configure Render to redirect `www` → apex (it does this when both are added).
* I have not changed any DNS records and need your explicit go-ahead (and access) to do so.

## 4. Environment variables

See `.env.example`. Secrets go in the hosting panel, **never** in Git.

| Variable | When | Purpose |
| --- | --- | --- |
| `SITE_URL` | build | Canonical domain (default `https://gegaattorney.al`). |
| `ALLOW_INDEXING` | build | `true` only after approval; otherwise `noindex` everywhere. |
| `FORM_SECRET` | runtime, **required in production** | ≥ 32 random chars (`openssl rand -hex 32`). Signs form tokens. |
| `MAIL_TRANSPORT` | runtime | `smtp` in production. (`log` = local testing only; refused in production unless `ALLOW_LOG_TRANSPORT=true`.) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` | runtime | SMTP account used to send the notifications. |
| `MAIL_FROM` | runtime | Sender – must be the SMTP account (or a verified alias). |
| `MAIL_TO` | runtime | Inbox that receives contact messages and appointment requests. |
| `PORT`, `HOST` | runtime | Set automatically by most hosts. |

### Email delivery

Option A – **use the existing Gmail address** (no extra cost, works immediately):
1. Enable 2-Step Verification on `gentjangega.lawoffice@gmail.com`.
2. Google Account → Security → *App passwords* → create one for "Website".
3. Set `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`, `SMTP_SECURE=true`,
   `SMTP_USER=gentjangega.lawoffice@gmail.com`, `SMTP_PASS=<app password>`,
   `MAIL_FROM` and `MAIL_TO` = the same address.
   Gmail's sending limits (hundreds of messages/day) are far above this site's needs.

Option B – **professional address on the domain** (e.g. `info@gegaattorney.al`), recommended for credibility:
requires an email host for the domain (e.g. Google Workspace, Zoho Mail, or the registrar's mail service – paid,
needs your approval) plus MX/SPF/DKIM records. The website only needs the new SMTP credentials; no code changes.

Either way: after deploying, send one test message from each form and confirm it arrives (and is not in spam).
Visitor messages are delivered with **Reply-To** set to the visitor, so "Reply" in the mailbox answers them directly.

## 5. Appointment booking – current state and options

Implemented now: a request workflow with a configurable weekly schedule (`src/config/availability.ts`:
Mon–Thu 09:00–12:00 & 14:00–16:00, Fri until 15:00, minimum 1 day ahead, maximum 60 days). **These hours are a
starting assumption and must be confirmed by the lawyer.** The fixed-date Albanian public holidays listed there
must also be verified, and movable holidays (Easter, Bajram) added each year.

If real-time availability is wanted later, options (none enabled – each needs your approval):

* **Google Calendar appointment schedules** (with a Google Workspace plan) – embed/link a booking page; lawyer
  manages availability in Google Calendar. Adds Google cookies/scripts → cookie consent needed.
* **Cal.com** (has a free tier; can be self-hosted) – link or embed; syncs with Google Calendar.
* Custom integration with the Google Calendar API on the existing server – most private, more development work.

The simplest privacy-friendly upgrade is to *link* (not embed) to an external booking page, keeping this site
cookie-free.

## 10. Items requiring the lawyer's review before publication

1. **Practice areas.** The six service pages are a draft based on the brief. Every example situation and
   "how I can help" item must be confirmed; remove anything not actually offered (e.g. family matters under
   *Çështje civile*, victims' representation under *Çështje penale*, civil-service disputes under
   *Çështje administrative*). No statutes, deadlines or outcome promises were written.
2. **Privacy policy.** Drafted against Law No. 124/2024 *"Për mbrojtjen e të dhënave personale"* (in force since
   February 2025, aligned with GDPR, with extraterritorial scope for services offered to people in Albania) and
   names the supervisory authority (Komisioneri për të Drejtën e Informimit dhe Mbrojtjen e të Dhënave Personale,
   idp.al). Legal bases are stated generically and flagged for verification against the specific articles.
3. **Legal notice.** References Law No. 55/2018 *"Për profesionin e avokatit në Republikën e Shqipërisë"* and the
   National Chamber of Advocacy's ethics rules. **I could not verify the Chamber's rules on lawyer advertising /
   website content** – the lawyer should confirm the site complies (tone is deliberately sober: no testimonials,
   no statistics, no success claims, no comparative claims). Also confirm whether any information (e.g. licence
   number, chamber registration) is mandatory to publish, and whether e-commerce/information-society disclosure
   rules apply (Albania's e-commerce framework was updated in 2025; not verified in detail).
4. **Cookies.** The site sets no cookies and loads nothing from third parties; the cookie policy says so. Any
   future analytics/embeds require consent first.
5. **Wording.** The Albanian copy uses the first person ("Ju kontaktoj…") for a personal tone. Confirm this voice
   is preferred over third person ("Av. Gega…").
